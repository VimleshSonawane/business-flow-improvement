   - Decision: Convert all timestamps to UTC (`timestamp`, ISO 8601 with Z). Keep the original value in `timestamp_original` and its offset in `utc_offset`. All milliseconds are .000, so seconds precision loses nothing.
   - Affected: 56,437 events converted.

6. **Events out of time order within a case**
   - Found: In file order, 0 events have an earlier timestamp than an event listed before them, in 0 cases. 10 events (in 10 cases) share an exact timestamp with an earlier event of the same case.
   - Decision: Flag in `out_of_order_in_file`. Sort each case by UTC timestamp, then by file position for ties, and record the result in `event_order` (1 = first). Timestamps are trusted over file order.
   - Affected: 0 events in 0 cases.

7. **Cases without a clear end**
   - Found: Last activity is `Payment Handled` in 10,043 cases and `Declaration REJECTED by EMPLOYEE` in 284 cases. 173 cases end on something else: Declaration SAVED by EMPLOYEE (134), Declaration REJECTED by MISSING (30), Declaration REJECTED by ADMINISTRATION (5), Declaration REJECTED by SUPERVISOR (4). Latest event in the log: 2019-06-17T15:30:58Z.
   - Decision: `is_complete` = yes when the last event is a payment (`Payment Handled`) or the employee closing a rejected declaration (`Declaration REJECTED by EMPLOYEE`); otherwise no. `end_status` gives which. Incomplete cases are kept and flagged, not removed.
   - Affected: 173 cases flagged incomplete.

8. **Cases that do not start with the employee**
   - Found: 0 cases start with an activity other than SUBMITTED or SAVED by EMPLOYEE.
   - Decision: Flag in `starts_with_submission`; keep.
   - Affected: 0 cases.

9. **2017 vs 2018 coverage**
   - Found: Cases by start year (Dutch local time): 2017 (2,240), 2018 (8,260). Events by year: 2017 (9,881), 2018 (45,921), 2019 (635). The dataset description says 2017 covers two departments only and 2018 covers all departments. The log has no department attribute, so this cannot be checked from the data.
   - Decision: Keep all years; add `year` (start year) to cases.csv. Any 2017-vs-2018 comparison must not be read as a trend. 2019 events belong to cases that started in 2018.
   - Affected: 2017: 2,240 cases, 2018: 8,260 cases.

10. **Amounts that are zero, negative or missing**
   - Found: Missing: 0. Zero: 446. Negative: 0. Range: 0.00 to 3292.54. Amounts are not whole euros (for example 26.85120450862128) because the publisher anonymised them.
   - Decision: Flag in `amount_flag`; keep the raw value unchanged in `amount`; no rows removed.
   - Affected: 446 cases flagged.

11. **How rejections are counted**
   - Found: `Declaration REJECTED by EMPLOYEE` occurs 1,365 times; 1,357 of these come straight after a rejection by an approver, so it is the employee responding to a rejection, not a new rejection. `Declaration REJECTED by MISSING` occurs 91 times (the approver role was not recorded).
   - Decision: `rejection_count` counts rejections by approvers (ADMINISTRATION, SUPERVISOR, PRE_APPROVER, BUDGET OWNER, MISSING) and excludes the employee step, which goes in `employee_rejection_count`. `rejected_at_least_once` = yes when `rejection_count` > 0.
   - Affected: 1,301 cases rejected at least once.

12. **Rare activities**

   - Decision: Keep all activities with their original names; nothing merged or renamed.
   - Affected: 3 events.

13. **Resource values**
   - Found: org:resource has only STAFF MEMBER (36,353), SYSTEM (20,084). People were anonymised by the publisher.
   - Decision: Keep as is; org:role is the useful organisational field.
   - Affected: None.

## Definition of a complete case

`is_complete = yes` when the case's last event, in time order, is `Payment Handled` (`end_status = paid`) or `Declaration REJECTED by EMPLOYEE` (`end_status = rejected`). Anything else is `no_clear_end`.

## Column notes

- `events.csv`: `timestamp` is UTC. `event_order` is the order by time within the case. `file_position` is the 0-based order in the raw file. `id` is the raw event id.
- `cases.csv`: `start`/`end` are the first and last UTC timestamps; `duration_days` = (end - start) in days, 4 decimals; `year` = start year in Dutch local time; `amount` is the raw value from the file.
